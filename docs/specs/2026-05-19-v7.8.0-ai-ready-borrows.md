# v7.8.0 — ai-ready borrows

> Borrows three patterns from `github.com/johnpapa/ai-ready` and adds a periodic repo-health entry point that ties them together. Continues the provenance/learning direction from v7.7.0.

## 1. Goal & scope

Ship four cohesive features as v7.8.0:

1. **PR review mining** — fetch the last N merged PRs (default 10) via `gh`, cluster repeated reviewer-feedback phrases, and emit candidate `[MINED:feedback]` principles into a side report (never auto-edits principles).
2. **12-asset AI-readiness scorecard** — bounded checklist of 12 named assets across 3 buckets (AI Context / Dev Workflow / Onboarding), rendered with `🟩🟨⬜` progress bars and a medal (🥉🥈🥇🏆).
3. **Monorepo cross-package ripple detection** — parse workspace manifests (pnpm, npm workspaces, Maven aggregator, Python `libs/`, dotnet `*.sln`) and emit downstream-package impact warnings in `spec-drift-detection` and `pre-commit-review`.
4. **`/mtk repo-health` entry point** — periodic command that runs scorecard + PR mining together. Surfaces a single shareable report; the user runs it from time to time.

### Out of scope (deferred)

- AGENTS.md / copilot-instructions auto-generation (different philosophy — MTK keeps these user-authored).
- CI / issue / PR template scaffolding.
- Per-area `.claude/instructions/{area}.md` isolation for mixed-stack repos.
- Automated promotion of `[MINED:feedback]` rules into CLAUDE.md (suggest-only this release).

### Classification

- **Scope:** feature (multi-skill, manifest-affecting)
- **security_impact:** low (read-only `gh` calls, no secrets written; depends on user's pre-existing `gh auth login`)
- **breaking_change:** no
- **Implementation path:** subagent (4 implementation batches + 1 release batch, ≥6 files, multi-skill)

## 2. EARS-style requirements

- **U1** When the engineer runs `/mtk repo-health`, the system SHALL produce a single markdown report containing the 12-asset scorecard, last-N PR mining results, and a top-3 actionable changes summary.
- **U2** The PR mining step SHALL fail-soft when `gh` is unavailable or unauthenticated, reporting a single warning line and continuing with the scorecard.
- **U3** The PR mining step SHALL default to the last 10 merged PRs and SHALL accept `--prs N` (range 1–50) to override.
- **U4** Mined phrases SHALL be tagged `[MINED:feedback]` with the source PR numbers cited; the system SHALL NOT auto-edit `architecture-principles.md`.
- **U5** When run in a monorepo, the system SHALL list cross-package ripples for staged files in `pre-commit-review` and for the change manifest in `spec-drift-detection`.
- **U6** The scorecard SHALL evaluate exactly the 12 named assets (no more, no less) and SHALL emit a deterministic medal based on the count of 🟩 (≥10 🏆, ≥8 🥇, ≥6 🥈, ≥4 🥉, else none).
- **U7** When `--json` is passed, the system SHALL emit machine-readable output to `.claude/repo-health-latest.json` alongside the markdown report.

## 3. The 12 assets (canonical list)

**AI Context bucket (4):**
1. `CLAUDE.md` present and non-empty
2. `.claude/references/architecture-principles.md` exists and has ≥5 tagged principles
3. `.claude/tech-stack` file present and matches a known `tech-stack-*` skill (or repo is non-MTK and skipped)
4. `tasks/lessons.md` exists with ≥1 entry

**Dev Workflow bucket (4):**
5. `docs/specs/` directory exists with ≥1 spec from the last 90 days
6. `docs/plans/` directory exists with ≥1 plan from the last 90 days
7. `.claude/manifest.json` and `.claude-plugin/plugin.json` versions match (when both present)
8. `bash scripts/validate-toolkit.sh` exits 0 (when present; missing = n/a, not penalized)

**Onboarding bucket (4):**
9. `README.md` exists and is non-empty
10. Build & test commands documented in CLAUDE.md or tech-stack skill (regex: `dotnet build|npm test|pytest|cargo test|go test|bash scripts/`)
11. `.claude/rules/` directory exists with ≥2 rule files
12. `.gitignore` excludes `.claude/settings.local.json` (and `.claude/analytics.json` if present)

Each asset is 🟩 (pass), 🟨 (partial / warning), or ⬜ (missing/fail). Scoring rubric lives in `.claude/references/repo-health-assets.md`. Assets that are "n/a" for this repo (e.g., asset 8 in non-MTK repos) are excluded from the medal denominator.

## 5. Public contracts

- **CLI:** `/mtk repo-health [--prs N] [--json] [--no-mining]` routed via `mtk`.
- **Output files:** `.claude/repo-health-latest.md` (always), `.claude/repo-health-latest.json` (with `--json`). Both are gitignored to avoid noise.
- **Script ABIs:**
  - `scripts/repo-health-score.sh [--json]` → stdout markdown (or JSON), exit 0 on any score, exit 2 on hard error.
  - `scripts/pr-review-mine.sh [--prs N] [--json]` → stdout markdown (or JSON), exit 0 always (mining is advisory).
  - `scripts/monorepo-ripple.sh <file>...` → stdout lines `RIPPLE <pkg>: affects <downstream-pkg>`, exit 0 always; no output when not a monorepo.

## 6. Test plan

- **Pressure test (`repo-health.md`):** ensure the skill refuses to fabricate scores when files are missing, requires citing PR numbers for mined phrases, and does not auto-edit principles.
- **Pressure test (`pr-review-mining.md`):** ensure the miner doesn't surface single-occurrence comments as rules and doesn't promote without `[MINED:feedback]` tag.
- **Manual on this repo:** run `scripts/repo-health-score.sh` against claude-helpers itself; expect 🥇 or 🏆 medal. Run `scripts/pr-review-mine.sh --prs 10` (best-effort, will fail-soft if `gh` not authed in session).
- **Validator:** `bash scripts/validate-toolkit.sh` must pass after manifest bump.

## 7. Risks & assumptions

- **R1:** `gh` CLI may not be authenticated → mining is opt-in, fail-soft, never blocks.
- **R2:** Repeated-phrase clustering may over-trigger on boilerplate ("LGTM", "thanks") → denylist in `pr-mining-patterns.md`.
- **R3:** Asset 8 (validate-toolkit) is MTK-specific; in non-MTK repos it should be skipped, not penalized → scorecard excludes n/a from denominator.
- **R4:** Monorepo detection in non-monorepo repos must be a no-op (no false positives).
- **A1:** Engineer accepts markdown-only output for the first cut; HTML/dashboard deferred.
- **A2:** Mining considers only PRs merged into the default branch (detected via `gh repo view --json defaultBranchRef`).

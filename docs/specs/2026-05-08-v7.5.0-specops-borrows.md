## Goal

Bundle four borrowed patterns from sanmak/specops into MTK as v7.5.0:
1. EARS notation + ANT test in spec authoring
2. Scored adversarial evaluator in code review and compliance
3. Dependency-introduction gate in security/pre-commit
4. Spec-linked structured learnings (`.mtk/learnings.jsonl`)

## Requirements (EARS)

### Ubiquitous (always true)
- **R1.** The `spec-driven-development` skill **shall** require every requirement statement to use EARS notation.
- **R2.** The `compliance-reviewer` agent and `code-review-and-quality` skill **shall** emit per-dimension 1–10 scores with file:line evidence quotes.
- **R3.** Captured corrections **shall** be persisted as structured JSON entries under `.mtk/learnings.jsonl`.

### Event-driven
- **R4.** When a spec is drafted, the `spec-driven-development` skill **shall** flag any tautological requirement (ANT test failure) before the approval gate.
- **R5.** When `spec-drift-detection` runs, it **shall** lint requirement statements for EARS conformance and report non-conforming lines as drift.
- **R6.** When `pre-commit-review` detects a change to a dependency manifest (`package.json`, `*.csproj`, `requirements.txt`, `pyproject.toml`, `go.mod`, `Cargo.toml`, `Gemfile`, `composer.json`), it **shall** invoke the dependency-intake checklist.
- **R7.** When `correction-capture` records a lesson, it **shall** append a structured entry to `.mtk/learnings.jsonl` and regenerate the human-readable `tasks/lessons.md` view.
- **R8.** When `spec-driven-development` or `fix` starts, the orchestrator **shall** retrieve relevant lessons via the 5-layer filter (proximity, recurrence, severity, validity, phase).

### State-driven
- **R9.** While a code review is in progress, if any scored dimension is below 7 the review status **shall** be `block`.
- **R10.** While a code review is in progress, if all dimensions carry the same score the review status **shall** be `auto-fail: non-discriminating`.

### Optional
- **R11.** Where the engineer asserts intent in writing, the EARS lint **may** accept non-EARS sentences in narrative sections (Goals, Background, Risks) but **shall not** accept them in the Requirements section.

### Unwanted behaviours
- **R12.** If review remediation has reached the third iteration on the same scored dimension, the workflow **shall** stop and escalate to a human rather than auto-iterate further.
- **R13.** If `tasks/lessons.md` is edited by hand, the next `correction-capture` run **shall** preserve manual additions by re-emitting them into `.mtk/learnings.jsonl` with `source: "manual"`.

## ANT check (self-applied)
None of R1–R13 are tautologies — each can be falsified by observing a counter-example in the implementation.

## Assumptions & Risks

- **A1.** `.mtk/` is gitignored in target repos but committed in this toolkit repo (per workflow-artifact pattern). `.mtk/learnings.jsonl` will be committed here only as an example/migration of existing `tasks/lessons.md`. **Risk:** team-wide canonical learnings live in `tasks/lessons.md` (committed). Mitigation: keep `tasks/lessons.md` as the canonical *team* store; `.mtk/learnings.jsonl` is the structured mirror, generated/regenerated. Manual edits to `tasks/lessons.md` are preserved on next migrate.
- **A2.** Existing target repos already on v7.4.0 will pull v7.5.0 via plugin update; their `tasks/lessons.md` will be migrated lazily on first `correction-capture` invocation. **Risk:** broken if target repo lacks `bash` or `jq`. Mitigation: `learnings.sh` falls back to pure-bash JSON emission (no `jq` dependency). If `bash` < 4, print warning and skip migration but don't error.
- **A3.** Scored evaluator changes the review contract. **Risk:** existing review prompts in target repos may produce non-scored output and confuse downstream tooling. Mitigation: scoring is additive — narrative review still produced; scores are an extra structured block. Backwards-compatible.
- **A4.** EARS lint may produce false positives on legitimate non-requirement prose. Mitigation: lint scopes to lines under `## Requirements` (and EARS subsections) only; ignores headings, lists outside that section, and code blocks.

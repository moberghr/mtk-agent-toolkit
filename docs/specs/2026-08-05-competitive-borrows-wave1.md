## Ambiguity gate

Resolved before drafting; no open decisions remain.

1. **JSON without `jq`.** S3.3 forbids external dependencies; `jq` is not on the allowed
   list, but `python3` is explicitly part of the accepted baseline. All JSON emission uses
   `python3`, matching the existing precedent in `run-benchmarks.sh:299-308`.
2. **Is `benchmarks/results.json` committed or generated-and-ignored?** Committed. The
   entire point of B1 is *publishing* the numbers; an ignored artifact publishes nothing.
   It is regenerated by `scripts/run-benchmarks.sh` and listed in `manifest.json` per C0.2.
3. **Does B2's hook block or inject?** Both, selected per-rule by a `strength` field.
   Default for existing MTK rules is `inject` (advisory) — turning four always-on rule files
   into hard blocks in one change would be an unreviewed behavior change to every session.
4. **Is `ABSTAINED` a third verdict or a flag?** A third verdict value. A flag on a `PASS`
   preserves exactly the failure mode being fixed: something reading `verdict == "PASS"`
   still sees a pass.

## Assumptions and risks

- `[VERIFIED:scripts/run-benchmarks.sh:377-386]` The benchmark runner already tracks global
  `PASS`/`FAIL`/`TOTAL` and calls `mtk_record_benchmark_run`. B1 adds *per-section*
  attribution, which does not exist today.
- `[VERIFIED:scripts/run-benchmarks.sh:367-369]` **Pre-existing defect found during
  spec research.** `VAL_OUT=$(bash scripts/validate-toolkit.sh 2>&1 || true)` followed by
  `VAL_EXIT=$?` always yields `0`, because `|| true` inside the command substitution makes
  the assignment succeed unconditionally. The assertion `validate-toolkit passes (exit 0)`
  therefore **cannot fail**. Publishing this as a measured number would publish a false
  number — which is precisely the failure mode B1 exists to prevent. In scope for B1
  (it is the correctness precondition for publishing), fixed in Batch A.
- `[VERIFIED:.claude/rules/git-workflow.md:1-12]` Rule files already carry `paths:` and
  `axes:` frontmatter. B2 extends this schema rather than inventing one.
- `[VERIFIED:.claude/references/review-finding-schema.md:22]` The verdict enum is
  `"PASS | NEEDS_CHANGES"` — there is no way for a reviewer to report "I could not review
  this" inside the schema. The agents' prose `## Self-Escalation` sections
  (`[VERIFIED:.claude/agents/test-reviewer.md:115-122]`) describe `BLOCKED` / `NEEDS_CONTEXT`
  but have no schema-valid channel to emit them, and no orchestrator rule consumes them.
- `[VERIFIED:hooks/hooks.json:26-56]` PreToolUse currently wires three hooks; adding a
  fourth follows the established `${CLAUDE_PLUGIN_ROOT}` + `mtk_is_redundant_plugin_invocation`
  pattern.
- **Risk:** a PreToolUse hook fires on *every* matched tool call. A slow or crashing
  rule-trigger hook degrades every session. Mitigation: fail-open on every error path,
  hard timeout in `hooks.json`, and an index-file fast path that exits before any parsing
  when no rule declares a trigger.
- **Risk (accepted, engineer-visible):** B2 changes what enters context on matched tool
  calls. Default `strength: inject` keeps it advisory.

## Success criteria

- **SC1** `hooks/rule-trigger.sh` delivers a matching rule's source content on a matched
  tool call and stays silent on a non-match.
- **SC2** The hook fails open: malformed frontmatter, missing index, or unreadable source
  never blocks a tool call.
- **SC3** `bash scripts/run-benchmarks.sh` writes `benchmarks/results.json` containing
  per-section pass/fail counts, a `measures` string, and an explicit `excludes` array.
- **SC4** The `validate-toolkit passes (exit 0)` benchmark assertion can actually fail
  (verified by observing a real non-zero exit propagate).
- **SC5** A reviewer that cannot complete emits `"verdict": "ABSTAINED"` with a populated
  `abstention.reason`, and the schema documents it.
- **SC6** The orchestrator must account for every dispatched lane; an abstained or missing
  lane cannot produce an overall `PASS`.
- **SC7** `bash scripts/validate-toolkit.sh` reports "Toolkit validation passed".

## Blocking dependency

`scripts/poison-lint.sh` uses `mapfile` (bash 4+); macOS ships bash 3.2, so
`validate-toolkit.sh` currently exits non-zero on this machine *before* any change here.
SC7 and C0.8 cannot be satisfied while it fails. This is a pre-existing defect, not caused
by this work. It must be resolved (fixed, or explicitly waived by the engineer) for this
spec to reach completion — surfaced at the approval gate rather than silently worked around.

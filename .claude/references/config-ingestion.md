# Config Ingestion — Existing AI-Assistant Configs

Read this companion from `setup-bootstrap` STEP 2.7 ("Ingest Existing
AI-Assistant Configs"). Repos migrating to MTK often already carry AI-assistant
configuration from other tools. Treat what's found as interview-grade input
feeding STEP 3 generation. **Ingestion is read-only:** source files are never
modified, moved, or deleted (File Preservation Policy applies).

## Detection list

Skip a file if it carries the `Auto-generated by MTK` marker — that means MTK
wrote it, it isn't "existing" config:

- `.cursorrules`, `.cursor/rules/*.mdc`
- `.github/copilot-instructions.md`
- `.windsurfrules`
- `.clinerules`
- `GEMINI.md`
- root `AGENTS.md` (skip if it carries the MTK auto-generated marker)
- pre-existing root `CLAUDE.md` body — only when bootstrap is re-running over a
  non-MTK `CLAUDE.md` (no `<!-- mtk-setup:` stamp)

## Extraction

For each found file: read it and extract concrete rule/convention candidates —
trigger-action rules, hard constraints, named conventions. Never copy generic
boilerplate or aspirational/marketing prose — same bar as setup-bootstrap's
"Rules for Generation". Each adopted candidate carries evidence anchor
`Evidence: migrated from <path>` (the real path — resolves under
`verify-claims`).

## Dedup and conflict rules

- **Dedup:** a rule the STEP 2 scan already derived is not duplicated from the
  ingested file.
- **Conflict:** an ingested rule contradicting a scan finding → emit a Needs
  review item citing both, same contract as the adaptive-interview re-run rule
  (STEP 2.5) — do not restate it here.
- **Report:** STEP 5 adds `Ingested AI configs: [list of source paths, or "none found"]`.

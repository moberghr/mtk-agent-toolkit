# MTK Environment Knobs

> Every `MTK_*` environment variable that changes MTK's behaviour, with its default and effect.
> Split out of `AGENTS.md` so the always-loaded constitution carries routing decisions, not a
> reference table (S2.26). Set these in the gitignored local settings override, never in shared
> settings.

| What you need | Variable | Effect |
|---|---|---|
| Silence the workflow-continuation nudge | `MTK_HOOKS_TIER2=0` in the local settings override | Silences `hooks/workflow-continuation.sh`, the async Stop nudge when a session ends with an unfinished workflow. The name outlived the retired tier-2 hook class; nothing else reads it. Default on |
| Enforce spec scope (hard deny) | `MTK_SCOPE_GUARD_ENFORCE=off\|advisory\|shadow\|active` | Mode of `hooks/scope-guard.sh` for an Edit/Write outside the approved spec's `change_manifest`/`test_manifest`. `advisory` (the default, unset) warns once per file per session; `active` is a hard PreToolUse deny (exit 2) every time — the legacy truthy values `1`/`true`/`yes`/`on` still mean `active`; `shadow` warns as advisory and also logs each would-be deny (`SCOPE-OUT-OF-MANIFEST`) to `.mtk/metrics/enforcement-shadow.jsonl`; `off` silences the hook |
| Auto-approve safe plans | `MTK_AUTO_PROCEED=1` | Skips Phase 2.5 prompt only when spec has no open decisions and no plan-gap BLOCKING findings |
| Disable artifact publishing | `MTK_ARTIFACT_PUBLISH=0` | Stops workflow skills publishing spec/plan/handoff/health to a claude.ai Artifact (data-egress opt-out for regulated repos); disk output is unaffected. See `.claude/references/artifact-publishing.md` |
| Pin MTK to a checkout | `MTK_HELPER_ROOT=/path/to/claude-helpers` | Makes MTK resolve from that checkout **first**, before the project copy and the plugin cache — covering both the `## MTK File Resolution` block every entry-point skill opens with and the inline script resolvers (`scripts/workflow-artifact.sh`, `scripts/learnings.sh`). Target-repo scripts resolve the *project* root from `$CLAUDE_PROJECT_DIR`/git, so their output always lands in the target |
| Allow interactive-prone shell commands | `MTK_INTERACTIVE_GUARD=0` | Disables the interactive-prompt check in hooks/security-gate.sh — the PreToolUse hard deny on Bash commands that can block on a prompt (S4.12): `gh pr merge` with no `--delete-branch`/`--no-delete-branch` decision, and prompt-capable commands piped through `tail`/`head`. Read-only pipes are never blocked |
| Disable the compaction archive | `MTK_COMPACT_ARCHIVE=0` | Stops `hooks/compact-archive.sh` (PostCompact) writing the compaction summary to `.mtk/sessions/<session>/compact-<stamp>.md`, which `hooks/session-start` offers on the next startup/clear on the same branch. Default `1` (on). The hook also writes nothing when `.mtk/` is not git-ignored in a git repo |
| Cap implementer tool calls | `MTK_IMPLEMENTER_MAX_CALLS=N` | The tool-call budget the orchestrator writes into each implementer brief (`subagent-implementation`). Past it the implementer returns `partial` with a `resume_note` and a fresh implementer resumes (max 2 respawns per batch). Default `120` |
| Declare that subagent dispatch is unavailable | `MTK_SUBAGENT_DISPATCH=0` | Tells `implement`'s Phase 2.9 pre-flight that this session cannot dispatch implementer subagents. HIGH/MAX then runs the **inline-MAX profile** (compensations C1–C3). It does **not** lower the rigor level. Default (unset) probes per run |
| Force or skip the pre-flight baseline | `MTK_BASELINE_CAPTURE=1` / `=0` | `implement` Phase 2.9 captures build/test/typecheck state at the base commit before the first edit. On by default at rigor HIGH/MAX; `=1` forces it at any level, `=0` opts out — and then every later checkpoint must state that no baseline exists |
| Tune or disable the host-load probe | `MTK_HOST_LOAD_MAX=N` / `MTK_HOST_LOAD_PROBE=0` | `scripts/host-load-probe.sh` reports the 1-minute load per core and says `overloaded` above `MTK_HOST_LOAD_MAX` (default `2.0`). An overloaded host routes the run to inline-MAX instead of dispatching implementers the harness watchdog will kill. `=0` skips the probe on shared CI runners |
| Cap parallel implementer waves | `MTK_BATCH_WAVE_MAX=N` | Phase 3 on the subagent path runs batches at the same `depends` level concurrently; this caps how many implementers one wave dispatches (default `3`). `1` restores fully sequential batches |
| Tune the mid-run churn review thresholds | `MTK_CHURN_REVIEW_LINES` / `MTK_CHURN_HALT_LINES` | Net non-generated lines changed since the last review before an early review (default 300) or a halt for `compliance-reviewer` (default 500). Defaults double at rigor HIGH/MAX. Generated files never count |
| Tune the collateral-churn thresholds | `MTK_COLLATERAL_*` (see `hooks/collateral-guard.sh`) | Thresholds for the guard that flags churn that is not the change you made: whitespace/EOL-only rewrites, generated artifacts riding along undeclared, asset directories regenerated wholesale, and structured files re-serialized around a small real edit |
| Write a tracked run receipt | `MTK_RUN_RECEIPT=1` | `implement` Phase 7.5 writes a **tracked** receipt beside the spec in `docs/specs/` holding the run's evidence (baseline vs final figures, gates, dispatch path, drift/coverage/collateral verdicts, reviewer lane outcomes). Fields never recorded are written as `not recorded` |
| Disable the lint-config weakening guard | `MTK_CONFIG_GUARD=0` | Disables `hooks/config-guard.sh`, the PreToolUse hard deny (exit 2) on Edit/Write that **weakens** a linter/analyzer/formatter config — adding suppression codes (`NoWarn`, `ignore`, `disable`, …), switching a rule or strictness setting off (`severity = none`, `"off"`, `TreatWarningsAsErrors=false`, …), or adding lines to an ignore file. Stricter edits and unrelated edits to the same files pass. Default on. Suppressions the engineer has explicitly approved go in `.mtk/config-guard-allow`, one repo-relative path per line; the list is honoured only while the file was modified in the last 24h, and an agent Edit/Write of the list itself is always denied. The deny message deliberately does not mention this knob or the allow list |
| Measure or relax the config-weakening deny | `MTK_CONFIG_GUARD_ENFORCE=off\|shadow\|active` | Mode of the config class of `hooks/config-guard.sh` (codes `W1-SUPPRESS`, `W2-DISABLED`, `W3-IGNORE`). `active` (the default) denies as described above; `shadow` allows the edit with no model-visible output and logs the would-be deny to `.mtk/metrics/enforcement-shadow.jsonl`; `off` allows silently. The deny on an agent edit of `.mtk/config-guard-allow` itself is not mode-gated. `MTK_CONFIG_GUARD=0` still turns both classes off. `advisory` or any other value falls back to `active` with one stderr line |
| Enforce the test-tamper check | `MTK_TEST_GUARD_ENFORCE=off\|shadow\|active` | Mode of the test class of `hooks/config-guard.sh`: an Edit/Write to a test-shaped code file that adds skip/focus markers (`T1-SKIP`) or suppressions (`T2-SUPPRESS`), drops test declarations (`T3-FEWER-TESTS`) or assertions (`T4-FEWER-ASSERTS`), or swaps a strong assertion for a weak one (`T5-WEAKENED`). `shadow` (the default) allows the edit with no model-visible output and logs the signal to `.mtk/metrics/enforcement-shadow.jsonl` — `mtk-doctor --usage` counts them per code; `active` denies (exit 2); `off` skips the check; `advisory` or any other value falls back to `shadow` with one stderr line. Approved test edits use the same `.mtk/config-guard-allow` list |
| Silence the push gate | `MTK_PUSH_GATE=0` | Disables `hooks/push-gate.sh`, the PreToolUse hook that runs only on `git push` (registered with an `if` filter) and checks the pushed range against a diff-bound review receipt (`scripts/review-receipt.sh`). Default on |
| Enforce the push gate | `MTK_PUSH_GATE_ENFORCE=off\|advisory\|shadow\|active` | Mode of `hooks/push-gate.sh` when the pushed range is not covered by a review receipt. `advisory` (the default, unset) prints one model-visible line and allows the push; `shadow` prints the same line and logs the would-be deny to `.mtk/metrics/enforcement-shadow.jsonl`; `active` is a hard PreToolUse deny (exit 2); `off` does nothing and prints nothing. In every mode but `off`, an unmapped push target (another refspec, `--all`, `git -C`, a `cd` earlier in the command) or a command the gate cannot classify is allowed with one line saying the receipt was not checked. An empty push range counts as covered |
| Silence the subagent context block | `MTK_SUBAGENT_CONTEXT=0` | Disables `hooks/subagent-context.sh`, the `SubagentStart` hook that hands an `mtk:` subagent (or any subagent while a workflow is live) the active workflow's context-pack path and the constitution's critical-rule ids as `additionalContext`. Context only — it never blocks. Default on |
| Change the Codex instruction byte cap | `MTK_CODEX_DOC_MAX_BYTES=N` | The byte limit `scripts/check-instruction-load.sh` applies to each root-to-directory `AGENTS.md` chain Codex concatenates (`CODEX-BYTES`; Codex truncates past it without saying so). Match it to your Codex `project_doc_max_bytes`. Default `32768` |
| Disable session cost tracking | `MTK_COST_TRACKER=0` | Disables the cost half of `hooks/cost-tracker.sh`, the async Stop recorder: it stops appending per-session token deltas (main thread and subagents) with an API-equivalent USD estimate to `.mtk/metrics/costs.jsonl`; `scripts/session-cost.sh window` sums a time window (the `implement` run receipt's cost field). Estimates only — priced from `hooks/lib/model-pricing.tsv`, not a bill. The same hook's other half, the `.claude/analytics.json` session stats (formerly `session-analytics.sh`), keeps running — this knob does not turn it off. Default on |

# Product Context Artifacts — product.md + decisions.md

Read only when `setup-bootstrap` STEP 3.8 runs.

## Rules for both files

- **Never (re)generated if present** — preserved untouched and reported in STEP 5; a later change routes through `.claude/references/regen-diff-contract.md`.
- **Evidence per claim or entry (mandatory):** a backticked path, a commit SHA, or `engineer interview — .claude/setup-answers.json (<key>)`. Nothing the scan or interview did not surface is written.
- Describe what the product **is**, not the roadmap — the same no-aspirational bar as bootstrap's Rules for Generation.
- Both writes pass the STEP 3.5c secret-scan gate. `product.md` is verified by `scripts/verify-claims.sh` in STEP 3.8 itself, because it does not exist yet at STEP 3.5a.

## product.md (≤40 lines)

Sources: the STEP 2 README/docs scan and interview question 7 (`answers.product_purpose`).

```markdown
# Product Context

> Auto-generated by setup-bootstrap. Describes what this product IS today. Every claim carries an evidence anchor.

## Purpose
[2–3 sentences. Evidence: engineer interview — .claude/setup-answers.json (product_purpose), or a README/docs path.]

## Users
[Who uses it and for what. Evidence: as above.]

## Key flows
- [3–6 bullets, one evidence path each, e.g. `src/api/checkout/`.]

## Non-goals
[Evidence-backed only; omit the section if nothing concrete surfaced.]
```

## decisions.md (ADR-lite, append-only)

A re-run may append entries; it never edits, reorders or deletes an existing one.

```markdown
## YYYY-MM-DD — <decision>

**Context:** [why it was needed]
**Decision:** [what was decided]
**Evidence:** [commit SHA, path, or interview key]
```

Seed on first generation from framework migrations and major version bumps in `git log` (cite the SHA), and from `hard_nevers` / `invisible_conventions` answers that gave a reason. If neither yields a concrete entry, write the header only: an empty log is correct; a fabricated one is not.

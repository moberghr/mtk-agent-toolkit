# AI Failure Modes Catalog

Research-cited catalog of patterns where AI-assisted development produces incorrect or misleading output. Each mode has a stable id (`F1`–`F14`), citation anchor, severity, a C#-flavored bad/good pair, and an imperative rule for reviewers. Load this file when reviewing AI-generated code at any rigor level; cite F-codes in review findings.

---

### F1 — Catch-All Error Swallowing

**Pattern.** Empty or log-only `catch` block consumes exceptions without propagating, rethrowing, or taking corrective action. The caller believes the operation succeeded.

**Citation.** Common in AI-generated try/catch scaffolding; frequently flagged in enterprise .NET audits.

**Severity.** must-fix

**Bad:**
```csharp
try { await ProcessPaymentAsync(order); }
catch (Exception) { /* ignore */ }
```

**Good:**
```csharp
try { await ProcessPaymentAsync(order); }
catch (Exception ex) when (!ex.IsTransient())
{
    _logger.LogError(ex, "Payment failed for order {OrderId}", order.Id);
    throw;
}
```

**Rule.** Every `catch` block must log, rethrow, or take a documented recovery action. A bare catch that only logs without rethrowing must include an explicit comment stating the intent to swallow.

### F2 — Hardcoded-Success Returns

**Pattern.** A method returns a hard-coded success value, completed task, or `true` without performing the actual work. Often introduced when an AI skips implementation and writes a stub.

**Severity.** must-fix

**Bad:**
```csharp
public async Task<bool> TransferFundsAsync(decimal amount, string to) => true;
```

**Good:**
```csharp
public async Task<bool> TransferFundsAsync(decimal amount, string to)
{
    var result = await _ledger.DebitAsync(amount);
    if (!result.Success) return false;
    await _ledger.CreditAsync(to, amount);
    return true;
}
```

**Rule.** Any method that returns a fixed literal for all inputs is a stub. Flag it as `critical` unless it is explicitly marked `// TODO:` or declared as a test double.

### F3 — Hallucinated APIs or Packages

**Pattern.** AI references a method, class, NuGet package, or npm module that does not exist in the cited version or at all.

**Severity.** must-fix

**Bad:**
```csharp
// MediatR 12 does not have ISender.DispatchAsync
await _sender.DispatchAsync(command);
```

**Good:**
```csharp
await _sender.Send(command, cancellationToken);
```

**Rule.** Any API call or package reference that cannot be found in the project's dependency manifests or official docs must be flagged. Do not assume the caller will notice a missing method at runtime. (Hallucinated *symbols cited in doc-comments* are a related smell — the `core/docdrift.txt` pack flags empty `<see cref="" />`; existence of the cited symbol still needs a reviewer.)

### F4 — Copy-from-Similar Drift

**Pattern.** Code is generated by copying a nearby implementation, inheriting its domain assumptions, field names, or magic values without adjustment.

**Severity.** should-fix

**Bad:**
```csharp
// Copied from OrderHandler without adjusting the status transition
entity.Status = OrderStatus.Shipped;   // should be InvoiceStatus.Sent
```

**Good:**
```csharp
entity.Status = InvoiceStatus.Sent;
```

**Rule.** When a generated block closely mirrors an adjacent handler or service, check every domain constant, enum value, and field name for context correctness. Flag any value that was plausibly copied unchanged.

### F5 — Defensive-Guard Bloat

**Pattern.** Excessive null checks, range assertions, or try/catch guards inserted around code that is already validated upstream, creating noise and masking real invariant violations.

**Severity.** worth-noting

**Bad:**
```csharp
// Order is never null here — it was validated at the command handler boundary
if (order == null) throw new ArgumentNullException(nameof(order));
if (order.Lines == null) order.Lines = new List<OrderLine>();
```

**Good:**
```csharp
// No guard needed: command handler validates non-null before reaching this layer
foreach (var line in order.Lines) { ... }
```

**Rule.** Each null-guard or defensive assertion must have an evident failure scenario within the current call chain. Guards added "just in case" obscure the actual invariant model and hide real bugs.

---

### F6 — Obvious-Comment Noise

**Pattern.** Comments restate the code in prose without adding domain intent, rationale, or edge-case warnings.

**Severity.** worth-noting

**Bad:**
```csharp
// Increment the counter
counter++;

// Call the repository to get the user
var user = await _repo.GetUserAsync(id);
```

**Good:**
```csharp
// Idempotency counter — prevents duplicate event processing on retry
counter++;
```

**Rule.** Flag comments that add no information beyond what the identifier names already convey. Require a rationale for any comment that survives: domain intent, invariant, or non-obvious constraint.

### F7 — Mock-Your-Own-DTOs

**Pattern.** Tests create and assert against AI-generated fake data objects (DTOs, response stubs) that are never connected to the real code path, giving false coverage.

**Severity.** should-fix

**Bad:**
```csharp
// Tests a fake DTO, not the real mapping
var result = new OrderDto { Id = 1, Total = 100m };
Assert.Equal(100m, result.Total);
```

**Good:**
```csharp
var command = new CreateOrderCommand(customerId: 42, lines: testLines);
var result = await _handler.Handle(command, CancellationToken.None);
Assert.Equal(expectedTotal, result.Total);
```

**Rule.** Any test that constructs its own expected output without invoking the system under test is testing the test, not the code. Flag as `should-fix`.

---

### F8 — Test Deletion Under Pressure

**Pattern.** AI removes or skips existing tests when they fail against new code rather than fixing the code or the test.

**Severity.** must-fix

**Bad:**
```csharp
// [Fact]  // commented out — test was failing after refactor
// public async Task Payment_Should_Reject_Negative_Amount() { ... }
```

**Good:**
```csharp
// Test updated to reflect new validation layer: negative amounts now throw DomainException
[Fact]
public async Task Payment_Should_Reject_Negative_Amount_WithDomainException() { ... }
```

**Rule.** Any deletion or `[Skip]` of an existing test must be accompanied by a stated reason in the commit. Deletions without rationale are `critical`.

### F9 — Fake Fallback Values

**Pattern.** An error path silently returns a default value (zero, empty string, null object) where the caller cannot distinguish success from failure.

**Severity.** must-fix

**Bad:**
```csharp
public async Task<decimal> GetBalanceAsync(string accountId)
{
    try { return await _bank.FetchBalanceAsync(accountId); }
    catch { return 0m; }   // caller cannot tell if balance is really zero
}
```

**Good:**
```csharp
public async Task<Result<decimal>> GetBalanceAsync(string accountId)
{
    try { return Result.Ok(await _bank.FetchBalanceAsync(accountId)); }
    catch (Exception ex) { return Result.Fail(ex.Message); }
}
```

**Rule.** Any catch that returns a domain-plausible default (0, empty list, null) is a silent failure. Use a discriminated result type or rethrow.

### F10 — Dead-Code Accretion

**Pattern.** Unused fields, methods, imports, or entire classes accumulate as AI generates variations and previous versions are never removed.

**Severity.** worth-noting

**Bad:**
```csharp
private readonly ILegacyPricingService _legacyPricing;  // never used
public decimal OldCalculateTotal(IEnumerable<OrderLine> lines) { ... }  // replaced
```

**Good:** Remove unreferenced members. If intentionally kept for future use, add a `// Retained for <reason>` comment.

**Rule.** Flag any private member, method, or import that is unreferenced within the file and has no stated reason for retention.

---

### F11 — Import or Namespace Breakage

**Pattern.** AI generates `using` directives or imports for namespaces that do not exist, were renamed, or belong to a different project in the solution.

**Severity.** must-fix

**Bad:**
```csharp
using MobergHR.Payments.Legacy.Adapters;  // namespace removed in v3
```

**Good:**
```csharp
using MobergHR.Payments.Adapters;  // current namespace post-migration
```

**Rule.** Unresolved `using` directives that survive a `dotnet build` cycle are `critical`. Flag any import that does not resolve in the current solution context.

---

### F12 — Docs Drift

**Pattern.** XML doc comments, README snippets, or OpenAPI descriptions describe the old contract after refactoring, creating a misleading public surface.

**Severity.** should-fix

**Bad:**
```csharp
/// <param name="orderId">The legacy numeric order ID.</param>
// Parameter is now a GUID after migration
public async Task<OrderDto> GetOrderAsync(Guid orderId) { ... }
```

**Good:**
```csharp
/// <param name="orderId">The order's stable GUID, allocated at creation.</param>
public async Task<OrderDto> GetOrderAsync(Guid orderId) { ... }
```

**Rule.** When a public method signature changes, its XML doc must be updated in the same commit. Flag any `<param>` or `<returns>` that describes a type or semantic the current signature does not match.

**Automated heuristic.** The `core/docdrift.txt` linter pack catches a subset of this mechanically (empty `<see cref="" />`, absolute reliability claims, placeholders, `[Obsolete]` without a message) — warning-level, never blocks. Semantic drift like the example above still needs a reviewer; the pack is the cheap first pass, F12 is the judgment pass.

### F13 — Async-Void Misuse

**Pattern.** AI writes `async void` for non-event-handler code, swallowing unhandled exceptions and preventing proper awaiting.

**Severity.** must-fix

**Bad:**
```csharp
public async void ProcessQueueItemAsync(QueueMessage msg)
{
    await _handler.HandleAsync(msg);
}
```

**Good:**
```csharp
public async Task ProcessQueueItemAsync(QueueMessage msg)
{
    await _handler.HandleAsync(msg);
}
```

**Rule.** `async void` is only acceptable for event handlers (e.g., `Button.Click`). Flag every other `async void` as `critical`.

---

### F14 — Silent ConfigureAwait Omission in Library Code

**Pattern.** Library or infrastructure code awaits without `.ConfigureAwait(false)`, risking deadlocks in synchronisation-context environments (ASP.NET Classic, WinForms).

**Severity.** should-fix

**Bad:**
```csharp
// In a reusable library — missing ConfigureAwait(false)
var result = await _httpClient.GetAsync(url);
```

**Good:**
```csharp
var result = await _httpClient.GetAsync(url).ConfigureAwait(false);
```

**Rule.** Library and infrastructure code must use `.ConfigureAwait(false)` on all awaits. Application-layer code (controllers, handlers) is exempt. Flag omissions in any `*.Infrastructure`, `*.Core`, or `*.Shared` project.
